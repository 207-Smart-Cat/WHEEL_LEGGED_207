# 科目三 Vision 页面 FSM 状态叠加设计

## 目标

在科目三单边桥和台阶流程运行期间，屏幕自动切换到 Vision 页面，保留现有相机、中线和赛道边界画面，并以红色大字号显示当前真实 FSM 阶段。流程结束后恢复进入前的页面。

## 状态来源与跨核同步

导航 FSM 运行在 Core0，Vision 页面运行在 Core1。Core1 不直接读取 `action_fsm`，而是从共享 IPC 状态读取一个专用的科目三显示状态枚举：

- `IDLE`：没有科目三桥/台阶流程正在执行。
- `TRACK_ALIGN`：正在执行视觉对齐。
- `ACTION`：正在执行当前航点的动作。
- `DONE`：动作已完成，等待导航层切换下一航点。

Core0 在每次 FSM 更新时发布该状态。Core1 仅用该字段显示，不参与或改变导航控制。

## 页面行为

1. Core1 检测到状态由 `IDLE` 变为非 `IDLE` 时，保存当前 UI 页面并自动进入 Vision 页面。
2. Vision 页面继续执行原有相机处理和绘制流程。
3. 每次画面刷新后，在 Vision 顶部信息区用红色 `16x16` 字体显示：
   - `TRACK ALIGN`
   - `ACTION`
   - `DONE`
4. 当共享状态回到 `IDLE` 时，恢复自动跳转前保存的页面。若用户在自动显示期间手动返回，正常按现有按键逻辑执行。

## 边界与安全

- 自动切换仅在科目三且状态为非 `IDLE` 时发生。
- 普通点不触发自动 Vision 页面。
- 显示链路只读 IPC 状态，不影响速度、航向、腿高、视觉控制或状态机转换。
- Core1 继续发送原有视觉 IPC 数据；状态叠加不替代相机处理。

## 验证

- 主机测试状态枚举到显示文案的映射。
- 静态检查：`TRACK_ALIGN`、`ACTION`、`DONE` 均由真实 FSM 映射而来。
- 目标端验证：桥、台阶到点后 Vision 页面自动打开，阶段文案按 FSM 切换；Done 后恢复原页面。
