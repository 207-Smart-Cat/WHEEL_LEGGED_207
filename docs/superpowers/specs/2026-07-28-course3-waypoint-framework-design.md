# 科目三航点打点框架设计

## 目标

在不改变科目一、科目二现有地图格式和遥控触发机制的前提下，建立科目三的三类型航点框架。屏幕选择科目三后，遥控器 SWB（CH4）决定每次打点的航点类型：普通、单边桥或台阶。

本阶段只记录和传递航点语义；单边桥与台阶不执行特殊控制。后续可在预留的动作状态机入口中分别接入子状态机。

## 不在范围内

- 不实现单边桥或台阶的控制、减速、姿态调整、触碰检测或完成条件。
- 不改动 `Navi_WayPoint_t` 的二进制布局、`record_point_map` 存储方式或现有地图加载流程。
- 不改变科目一或科目二的 SWB 映射。

## 用户操作和数据流

1. 用户在屏幕选择 `VEHICLE_MODE_COURSE_3`，并进入既有导航打点模式（Driver=2、Map=1）。
2. 用户将 CH4 置于所需挡位；CH6 的既有、去抖后的边沿触发一次打点。
3. 第一次打点继续建立 `WP_TYPE_HOME` 原点；之后的打点记录当前 `x`、`y`、`yaw`、`type`、`action_cmd` 和 `valid` 到 `record_point_map`。
4. 发车时，既有逻辑将 `record_point_map` 复制到 `point_map`；`navi_parse_global_path()` 解析导航路径；循迹层按顺序到达航点。

科目三的打点位置是接近器材且保持安全距离的位置，而不是器材边缘、桥面中心或台阶接触点。

## SWB 类型映射

| CH4 标定值 | 航点类型 | 当前运行行为 |
| --- | --- | --- |
| 192（低位） | `WP_TYPE_NORMAL` | 普通循迹，达到阈值后切换下一点。 |
| 992（中位） | `WP_TYPE_BRIDGE` | 记录桥语义；当前不接管控制，按普通循迹通过。 |
| 1792（高位） | `WP_TYPE_JUMP` | 记录台阶语义；当前不接管控制，按普通循迹通过。 |

使用现有阈值分段：`< 800` 为低位，`800..1400` 为中位，`> 1400` 为高位。该划分对 192、992、1792 三个标定值保留余量。

## 分层与改动边界

### `remote.c`

`Remote_GetRecordPointType()` 按 `Runtime_Get_Vehicle_Mode()` 分支：

- 科目二保留现有映射：普通 / 排雷 / 台阶。
- 科目三映射为普通 / 单边桥 / 台阶。
- 其他模式始终返回普通点。

CH6 触发、遥控使能检查、去抖与写入 `wifi_remote_type` 的既有逻辑不变。

### `navigation_tracking.[ch]`

继续通过 `navi_auto_record_task()` 写入 `record_point_map`，并继续通过 `get_enum_name()` 输出类型名称。无需新建科目三专属地图或存储结构。

### `navigation_action.[ch]`

保留 `WP_TYPE_BRIDGE` 与 `WP_TYPE_JUMP` 对应的状态机枚举和后续挂载点，但本阶段不将它们加入 `action_seq`，也不设置 `is_action_busy`。因此它们不会阻断循迹层的普通到点切换。

为使后续扩展清晰，动作解析处应明确注释：当科目三子 FSM 开始实现时，桥和台阶类型必须同时加入动作序列；相应子 FSM 完成后必须通过 `action_done_pending/action_done_idx` 回执，导航层才能切下一个点。

## 错误处理与兼容性

- 遥控失联、CH5 未使能、未进入打点模式、位姿无效、地图已满时，保持既有安全行为，不新增写点。
- 首点始终是 `HOME`，不受 CH4 挡位影响。
- 已保存的科目一、二地图继续按其已记录的 `type` 执行；本次不迁移历史数据。

## 验证标准

1. 屏幕选择科目三、进入打点模式后，低/中/高 CH4 配合 CH6 分别记录 `NORMAL`、`BRIDGE`、`JUMP`。
2. 打点预览和日志能够显示三种中文类型。
3. 发车加载打点地图后，三个类型都能按原顺序到点并切换下一点，不因桥或台阶类型卡住。
4. 科目二的中位 CH4 仍记录 `MINE_SWEEP`，证明模式隔离正确。
